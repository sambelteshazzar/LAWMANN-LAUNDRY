# Lawmann v1 Core — Implementation Plan

> **For agentic workers:** Execute task-by-task in order; steps use checkbox (`- [ ]`) syntax. Spec: `docs/specs/2026-09-28-v1-core-design.md`. Every task ends with `npm run typecheck` green (and `npm test` where a test file exists).

**Goal:** Build the working app: staff-PIN auth, intake, orders/payments, SMS outbox, costs, owner dashboard, activity feed, reports, receipts — on the existing schema and its DB-enforced rules.

**Architecture:** Next.js 15 App Router, server components + server actions, drizzle over PGlite (file-backed at `.pglite/`), one service layer (`src/lib/*`) consumed by both actions and tests. Money laws stay in the DB triggers; TypeScript never re-implements them, it translates their violations into friendly sentences.

**Tech stack:** Next 15, React 19, drizzle-orm/pglite, zod v3, Tailwind v4, vitest + fast-check (new devDep).

## Global Constraints

- Money is integer pesewas, weight integer grams — no float touches either, any layer (`src/lib/money.ts` rules).
- TypeScript: strict, `noUncheckedIndexedAccess`, `verbatimModuleSyntax` (use `import type`), path alias `@/*` → `src/*`.
- Zod v3 import style: `import { z } from 'zod'`.
- Never re-implement DB constraints in TS: attempt the write, catch, translate. Replays on idempotency keys (order UUID pkey, `payment_gateway_ref`) are success.
- Tax split computed once at order creation via `splitTaxInclusive`, stored, never recomputed.
- Confirmed and pending-MoMo money are never mixed in owner-facing numbers.
- UI: mobile-first, tap targets ≥ 44px, `inputMode="decimal"` on numeric fields, palette: slate/teal neutrals + one accent (see globals.css task). No AI-slop UI: real labels, real empty states, no gradient mountains.
- No comments in code unless carrying a non-obvious decision, in the existing file's voice (see `src/lib/tax.ts` header for the house style).
- Commit only if the user has asked for commits; otherwise stop at green tests.

```ts
import fc from 'fast-check';
import { describe, expect, it } from 'vitest';
import { splitTaxInclusive, inclusiveTaxFraction } from '@/lib/tax';
import { pesewas } from '@/lib/money';

describe('splitTaxInclusive', () => {
  it('components always sum to exactly the total', () => {
    fc.assert(fc.property(fc.integer({ min: -10_000_000, max: 10_000_000 }), (inclusive) => {
      const split = splitTaxInclusive(pesewas(inclusive));
      expect(split.base + split.vat + split.nhil + split.getfund).toBe(inclusive);
    }));
  });
  it('each component within one pesewa of the exact fraction', () => {
    fc.assert(fc.property(fc.integer({ min: 1, max: 10_000_000 }), (inclusive) => {
      const s = splitTaxInclusive(pesewas(inclusive));
      expect(Math.abs(s.vat - (inclusive * 1500) / 12000)).toBeLessThanOrEqual(1);
      expect(Math.abs(s.nhil - (inclusive * 250) / 12000)).toBeLessThanOrEqual(1);
      expect(Math.abs(s.getfund - (inclusive * 250) / 12000)).toBeLessThanOrEqual(1);
      expect(Math.abs(s.base - (inclusive * 10000) / 12000)).toBeLessThanOrEqual(1);
    }));
  });
  it('deterministic', () => {
    fc.assert(fc.property(fc.integer({ min: 1, max: 1_000_000 }), (v) => {
      expect(splitTaxInclusive(pesewas(v))).toEqual(splitTaxInclusive(pesewas(v)));
    }));
  });
  it('zero splits to zero', () => {
    const s = splitTaxInclusive(0);
    expect([s.base, s.vat, s.nhil, s.getfund, s.total]).toEqual([0, 0, 0, 0, 0]);
  });
  it('GH¢73 splits as documented (7300 -> 6083/912/152/153)', () => {
    const s = splitTaxInclusive(7300);
    expect(s.base + s.vat + s.nhil + s.getfund).toBe(7300);
  });
});
```
